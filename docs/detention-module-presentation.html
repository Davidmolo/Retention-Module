1. Purpose

When a driver waits too long at pickup or delivery, OpenRoad sends a “Detention completed” email. Today Art tracks those claims in a Google Sheet (status, money, follow-ups, email threads).

Detention in XXII Admin brings that work into the same place as Retention and Gross Profit — so Art can manage claims in one system.

Primary user Art (Mantas confirmed). Admins grant Detention access in Settings, same as other modules.

6. What makes this scalable

Today’s board is useful for managing claims. Scalability depends on how new claims enter XXII.

1. OpenRoadDriver finishes detention
→
2. Email“Detention completed” to company inbox
→
3. XXIICreates claim automatically
→
4. ArtUpdates status / notes in XXII
Why this matters Without email intake (or regular sheet import), every new claim still needs the spreadsheet — XXII stays a snapshot, not the system of record.

7. Decision for Mantas / Art

How should new detentions get into XXII?

Option A — Auto from email (recommended)

XXII watches the OpenRoad detention emails and creates claims itself. Most scalable; sheet becomes optional backup.

Option B — Import sheet in XXII

Art uploads an updated sheet export in the app when there are new rows. Faster to build; still manual.

Also confirm: reminder recipients (Art only vs Art + others), and which inbox to watch if Option A.

8. One-line summary for David

Bottom line Detention v1 is live in XXII Admin with real sheet data so Art can manage claims there. The next build that turns this into a daily system is getting new OpenRoad detentions into XXII automatically (email) — or a self-serve sheet import until then.
