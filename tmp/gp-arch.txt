Gross Profit Module — Architecture & Data Flow
Prepared for: Mantas A. / XXII Century
Application: admin.goxxii.com/gross-profit
Stack: Next.js + MySQL · Settlement week: Tuesday → Monday
Document date: October 21, 2026 
1. Purpose
This document describes how the Gross Profit module is built: which external systems it uses, how weekly reports are generated, and how the admin UI displays results. 
Key principle: The UI reads a stored weekly report (gross_profit_reports). It does not recalculate from live APIs on every page load. Fresh
numbers require Phase A (sync) + Phase B (compute & store).

11. Summary for stakeholders
The Gross Profit module syncs OpenRoad (drivers, loads, routes, compensations, load financials / accessorials), Samsara (MPG), Relay (OO fuel), and PrePass (tolls) into MySQL, then
computes and stores a Tuesday–Monday weekly report. The admin site displays that stored report. Company fuel uses miles÷MPG×PPG; OO fuel follows the agreed exception rules;
pay is compensation plus OpenRoad accessorials for the settlement week; multi-driver loads use route shares, not full linehaul.
